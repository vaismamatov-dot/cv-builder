# Резюме — личная мастерская

Локальное веб-приложение по [PRD](./PRD.md), [SPEC](./SPEC.md) и [DESIGN](./DESIGN.md). Тёплый рабочий экран, сиреневые закладки, редактируемая анкета и настоящий PDF-предпросмотр.

[Открыть сайт](https://vaismamatov-dot.github.io/cv-builder/) · [Репозиторий](https://github.com/vaismamatov-dot/cv-builder)

## Версия для GitHub Pages

Сборка `npm run build:pages` создаёт статический сайт в `out/` с префиксом `/cv-builder`. Для другого имени репозитория задайте `NEXT_PUBLIC_BASE_PATH=/<имя-репозитория>` перед сборкой. Редактор, фото, IndexedDB и оба PDF-формата работают в браузере. ИИ в этой сборке принудительно выключен: GitHub Pages не запускает серверный API. Исходный API сохранён для обычного Next.js-размещения.

Workflow `.github/workflows/pages.yml` запускает тесты, собирает сайт и публикует его при push в `main`. В настройках репозитория Pages должен использовать источник **GitHub Actions**. Секреты ИИ для этой публикации не нужны и в статическую сборку не передаются. На GitHub Pages черновик будет отдельным от черновика на localhost.

## Запуск

Требуется Node.js 22.13+; разработка и проверки выполнены на Node.js 26.13.0.

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). Используйте один адрес постоянно: localhost и 127.0.0.1 имеют разные хранилища браузера. Файлы PDF.js для предпросмотра копируются автоматически перед запуском и сборкой.

Для production-сборки:

```sh
npm run build
npm run start
```

Перед переустановкой зависимостей на Windows остановите сервер через Ctrl+C: нативные библиотеки Next.js могут быть заблокированы работающим процессом.

## Что работает

- Форма с именем, должностью, фото, датой рождения, контактами, опытом, навыками, образованием, проектами, курсами, описанием и сильными сторонами.
- Загрузка и кадрирование JPEG, PNG и WebP; фото обрабатывается и хранится локально.
- Автосохранение в IndexedDB, восстановление черновика, защита от одновременной записи из вкладок, ручной перехват редактирования.
- Три шаблона, пять цветов документа, скрытие и перестановка разделов, порядок записей опыта.
- Предпросмотр фактического PDF через PDF.js; экспорт A4 и Mobile с кириллицей, текстовым слоем, ссылками и нумерацией.
- Адаптивный редактор и отдельный мобильный предпросмотр.
- Серверный API ИИ, согласие, проверка ответов, предложения по разделам, ручное редактирование, применение, отмена и защита от устаревших ответов.

По умолчанию приложение начинает с пустого резюме. В `tests/fixtures` находятся исключительно синтетические данные для проверок. Сведения, введённые во время ручной проверки браузера, являются тестовым примером.

## ИИ

ИИ выключен по умолчанию. Для ручного редактирования и PDF ключ не требуется. Подготовлен адаптер Gemini; реальные запросы не выполнялись, поскольку ключ и выбранная модель не предоставлены.

1. Скопируйте `.env.example` в `.env.local`.
2. Укажите `AI_API_KEY`, `AI_MODEL` и Redis REST-реквизиты `RATE_LIMIT_REDIS_URL`, `RATE_LIMIT_REDIS_TOKEN`, `RATE_LIMIT_HASH_SECRET`.
3. Укажите имя провайдера и ссылку на его условия. Ознакомьтесь с политикой провайдера, настройками хранения и дополните `/privacy` перед публичным запуском.
4. Установите `AI_ENABLED=true` и перезапустите dev-сервер. Для production повторите сборку: доступность ИИ вычисляется на серверной странице во время сборки.

Ключ используется только сервером. В API передаются только разрешённые профессиональные поля; имя, фото, дата рождения, контактные поля, URL проектов и скрытые разделы исключены. Контакты внутри свободного текста маскируются по шаблонам, которые не способны распознать все возможные личные сведения.

Лимиты: 5 запросов/минуту и 30/час на сессию, 100/час на хеш IP; один активный запрос на сессию. Тело — до 128 КиБ. При недоступном Redis запросы к платному провайдеру не выполняются. Автоматических платных повторов нет.

На production размещение должно доверять `X-Forwarded-For` только от своего прокси. Отдельный месячный денежный лимит задаётся в кабинете провайдера: счётчики приложения его не заменяют.

## Данные

Один черновик и фото находятся в IndexedDB текущего браузера. Очистка браузера удаляет их. Скачанный PDF — самостоятельный файл; удаление черновика не удаляет скачанные файлы. Серверная база резюме, внешняя аналитика и запись пользовательских сессий не подключены.

PDF создаётся в Web Worker на устройстве. Имя, контакты и фото не отправляются серверу для экспорта. Шрифты Noto Sans поставляются локально, лицензия находится в `public/fonts/OFL.txt`; интерфейсные шрифты поставляются пакетами Fontsource.

## Проверки

```sh
npm run typecheck
npm test
npm run test:pdf
node scripts/render-pdf.mjs
npm run build
```

`test:pdf` создаёт 30 сочетаний шаблонов/цветов/форматов и 6 длинных документов в `outputs/pdf-check`. Проверяет размеры, кириллицу, скрытые поля, присутствие всего опыта, многостраничность и нумерацию. `render-pdf.mjs` формирует PNG для визуального просмотра. Результаты тестов не входят в приложение.

Код формы использует управляемую неизменяемую модель React и Zod. React Hook Form из исходного предложения стека пока не используется; API и модель SPEC сохранены. Нумерация добавляется через pdf-lib после верстки: это обход обнаруженного дефекта динамического текста с пользовательскими шрифтами в PDF-движке. Предпросмотр и скачивание получают одинаковые окончательные байты.

Состояние проверки и оставшиеся ограничения: [docs/implementation-status.md](./docs/implementation-status.md).
