# SPEC — Конструктор резюме

Версия: 1.0  
Дата: 17 ноября 2026 года  
Основание: [PRD.md](./PRD.md), версия 1.0  
Статус: техническая спецификация MVP; реализация ещё не выполнена.

## 1. Назначение и границы

Документ определяет структуру приложения, модель данных, контракты интеграций, правила обработки состояний и проверку требований PRD. При расхождении продуктовых требований приоритет имеет PRD; изменения области MVP сначала отражаются в нём.

MVP — русскоязычное веб-приложение без регистрации. Одно резюме хранится на устройстве пользователя. ИИ предлагает текст, пользователь подтверждает изменения, PDF формируется локально в форматах A4 и Mobile. Аккаунты, серверное хранение резюме, оплата и публикация по ссылке в эту реализацию не входят.

## 2. Технические решения

Базовый стек для реализации:

- TypeScript и Next.js с React: интерфейс и серверный API в одном проекте.
- React Hook Form и Zod: управление полями, общие схемы и валидация.
- IndexedDB: черновик, обработанная фотография и согласие на работу ИИ.
- `@react-pdf/renderer`: единое дерево PDF для предпросмотра и скачивания; генерация в Web Worker после проверки совместимости сборки.
- PDF.js: отображение страниц созданного PDF в интерфейсе.
- Vitest: проверки модели, преобразований и API; Playwright: пользовательские сценарии.
- Серверный адаптер ИИ с независимым от провайдера контрактом.
- Redis-совместимое хранилище для краткоживущих счётчиков ограничений API; содержимое резюме туда не записывается.

Это проектные решения, а не описание существующего кода. Версии пакетов фиксируются lock-файлом при инициализации. До разработки основного интерфейса необходимо проверить техническим прототипом кириллицу, переносы страниц, порядок извлечения текста и работу PDF Worker на iOS Safari. При невозможности выполнить требования выбранным PDF-движком решение пересматривается до реализации шаблонов.

PDF создаётся на устройстве: фотография, имя и контакты не передаются серверу для экспорта. Сервер обслуживает только запросы генерации текста и не хранит резюме.

## 4. Модель данных

### 4.1. Базовые типы

```ts
type ID = string; // crypto.randomUUID()
type Month = string; // YYYY-MM, проверяется схемой
type DateOnly = string; // YYYY-MM-DD, без часового пояса
type TemplateId = 'classic' | 'modern' | 'minimal';
type ThemeId = 'graphite' | 'blue' | 'green' | 'burgundy' | 'purple';
type PdfFormat = 'a4' | 'mobile';
type SectionId = 'summary' | 'strengths' | 'experience' | 'skills'
  | 'education' | 'projects' | 'courses';

interface Experience {
  id: ID;
  company: string;
  position: string;
  start: Month | null;
  end: Month | null;
  current: boolean;
  responsibilities: string[];
  achievements: string[];
}

interface Education {
  id: ID;
  institution: string;
  specialty: string;
  level: string;
  startYear: number | null;
  endYear: number | null;
  current: boolean;
  details: string;
}

interface Skill { id: ID; name: string; group: string | null }
interface Strength { id: ID; text: string }
interface Project {
  id: ID;
  name: string;
  kind: 'personal' | 'educational' | 'other';
  description: string;
  url: string;
}
interface Course {
  id: ID;
  name: string;
  organization: string;
  year: number | null;
}

interface Resume {
  schemaVersion: 1;
  id: ID;
  revision: number;
  updatedAt: string; // ISO UTC
  personal: {
    fullName: string;
    targetPosition: string;
    birthDate: DateOnly | null;
    showBirthDate: boolean;
    photoAssetId: ID | null;
    showPhoto: boolean;
  };
  contacts: {
    phone: string;
    email: string;
    city: string;
    telegram: string;
    links: { id: ID; label: string; url: string }[];
  };
  summary: string;
  strengths: Strength[];
  noExperience: boolean;
  experience: Experience[];
  education: Education[];
  skills: Skill[];
  projects: Project[];
  courses: Course[];
  presentation: {
    template: TemplateId;
    theme: ThemeId;
    hiddenSections: SectionId[];
    sectionOrder: SectionId[];
    experienceOrder: 'recent-first' | 'manual';
  };
}
```

Порядок элементов в массивах — порядок отображения. В режиме `recent-first` места работы сортируются по дате начала по убыванию, записи без даты идут последними, при равенстве сохраняется порядок. Ручная перестановка включает `manual`. Установка `noExperience` скрывает опыт, сохраняя записи; снятие флага восстанавливает их.

Значения по умолчанию: пустые строки и массивы, nullable-даты, `showBirthDate=false`, `showPhoto=true`, `template=classic`, `theme=graphite`. Порядок разделов: описание, сильные стороны, опыт, навыки, образование, проекты, курсы. Контакты и заголовок всегда находятся в начале документа; в Modern контакты размещаются в боковом блоке.

### 4.2. Фото

В object store `assets` хранится `{ id, blob, mime, width, height, crop }`. Бинарные данные не входят в JSON модели. `crop` содержит нормализованные координаты области и масштаб. Для MVP достаточно хранить обработанное изображение и координаты для повторного кадрирования в пределах сохранённого изображения; для выбора другой области исходника пользователь может загрузить его повторно.

### 4.3. Версии и изменения

Каждая команда редактирования увеличивает `revision` и обновляет `updatedAt`. Фокус, масштаб предпросмотра и открытая вкладка модель не меняют. Даты рождения сравниваются с локальной календарной датой пользователя без преобразования через UTC.

## 5. Валидация и ограничения

Три независимых режима проверки: `draft` разрешает незаполненные поля; `ai` проверяет готовность исходных сведений; `export` проверяет обязательные данные и заполненные видимые записи.

- Ф. И. О.: 1–150 символов после удаления внешних пробелов; не ограничивать число слов и национальный формат имени.
- Желаемая должность: 1–150 символов.
- Компании, должности, учебные заведения, названия проектов и курсов: до 200 символов.
- Описание: до 3 000 символов; пункт обязанностей, достижений или сильной стороны: до 1 000 символов.
- Навык: до 80 символов, максимум 100 навыков.
- Максимум 20 записей каждого повторяемого раздела, 30 пунктов обязанностей и 30 достижений на место работы, 20 сильных сторон, 10 контактных ссылок.
- Общий объём текстовых полей модели: до 50 000 символов. Эти пределы — технические ограничения MVP; интерфейс показывает счётчики рядом с достижением лимита.
- Для генерации: заполнены имя и должность и имеется содержательный видимый источник. Имя проверяется локально и в запрос не включается.
- Для экспорта: имя, должность и минимум один валидный телефон или email. Если оба контакта введены, проверять оба.
- Для непустого видимого опыта обязательны компания, должность и начало; для завершённой работы также окончание. `current=true` очищает окончание после подтверждения, если оно было заполнено.
- Для непустого образования обязательно учреждение; год окончания либо `current=true`. Будущий год окончания допустим для образования; будущие даты фактически начавшейся работы не допускаются.
- Для проекта обязательно название, для курса — название; остальные поля необязательны.
- Полностью пустая повторяемая запись не экспортируется. Незавершённая видимая запись блокирует экспорт с указанием поля. Скрытые записи экспорт не блокируют.
- Телефон допускает международный префикс, пробелы, скобки и дефисы. После нормализации — 7–15 цифр; не навязывать код страны. Ссылка `tel:` строится из нормализованного номера.
- Email проверяется схемой email, длина до 254 символов. HTTP-ссылки поддерживают только `https:` и `http:`; `javascript:`, `data:` и `file:` запрещены.
- Telegram принимает `@username` или HTTPS-ссылку `t.me/username`, сохраняется и отображается нормализованно.
- Навыки разделяются по запятым, сравниваются без учёта регистра после нормализации пробелов. При дубле сохраняется первое написание, уведомление позволяет отредактировать его.

Ограничения проверяются до записи нового значения без молчаливого обрезания текста. Сервер независимо проверяет собственную входную схему.

## 6. Интерфейс и состояния

### 6.1. Компоновка

Единственный рабочий экран `/`: заголовок, статус сохранения, редактор разделов, панель оформления, предпросмотр и действие скачивания. На ширине от 1024 px редактор и предпросмотр находятся рядом; ниже — вкладки «Редактор» и «Предпросмотр». Минимальная ширина интерфейса — 360 px. Сам лист PDF масштабируется в доступную область.

Секции редактора: личные данные, контакты, описание, опыт, навыки, образование, проекты, курсы, сильные стороны. Перестановка доступна кнопками «Выше»/«Ниже» и при необходимости перетаскиванием. Скрытие раздела сохраняет его содержание. У фото и даты рождения собственные переключатели видимости.

При скачивании открывается выбор двух форматов с размерами страниц, текущим количеством страниц и кнопкой скачивания. На любом устройстве доступны оба формата.

### 6.2. Независимые состояния

- Сохранение: `loading → saved | empty | error`, после изменения `dirty → saving → saved | error`.
- ИИ: `idle → consent → generating → proposal | error`; предложение дополнительно имеет флаг `stale`.
- PDF: `idle → rendering → ready | error`.
- Фото: `idle → validating → cropping → processing → ready | error`.

Ошибки одного процесса не очищают данные другого. Действия «Новый документ» и «Удалить все данные» требуют подтверждения. Удаление непустой записи предоставляет немедленную отмену.

Поля имеют label, ошибки связаны через `aria-describedby`, статусы сообщаются через `aria-live`. После ошибки экспорта фокус переходит к первому проблемному полю. Диалоги удерживают фокус и возвращают его к кнопке открытия.

## 7. Сохранение и восстановление

База IndexedDB `resume-builder`, stores `drafts`, `assets`, `preferences`. В `drafts` хранится одно активное резюме. Согласие хранится отдельно с версией текста политики; при смене провайдера или условий требуется повторное согласие.

Изменения записываются с debounce 300 мс; фото и ссылка на него — одной транзакцией. Индикатор «Сохранено» появляется только после успешного commit. Попытка flush при уходе со страницы является дополнительной мерой и не заменяет регулярную запись. При ошибке сохранения данные остаются в памяти и показывается постоянное предупреждение.

Миграции выполняются до редактирования. Неизвестная более новая версия не перезаписывается; показывается ошибка совместимости и возможность скачать исходный черновик как файл восстановления. Повреждённый черновик не удаляется автоматически.

При открытии второй вкладки использовать BroadcastChannel: уведомить об активном редакторе и открыть вторую вкладку в режиме чтения до явного перехвата. Запись дополнительно сравнивает ожидаемую `revision` с сохранённой в транзакции; при конфликте автоматическая перезапись запрещена.

«Удалить все данные» отменяет активные запросы, увеличивает внутренний идентификатор сессии, очищает хранилища, таймеры, undo и PDF-кэш, освобождает object URL. Поздние ответы старой сессии игнорируются, чтобы данные не восстановились после удаления. «Новый документ» выполняет такую же очистку содержимого, сохраняя актуальное согласие и предпочтения интерфейса.

## 8. Работа с фотографией

1. Проверить размер до 10 МБ, сигнатуру JPEG/PNG/WebP и успешное декодирование; одного расширения недостаточно.
2. Отклонить изображение свыше 40 мегапикселей с понятной подсказкой уменьшить исходник.
3. Нормализовать EXIF-ориентацию один раз, показать квадратное кадрирование и масштабирование.
4. Сохранить обработанное изображение до 1200 × 1200 px, целевой размер до 500 КБ. Перекодирование удаляет метаданные; прозрачный фон при преобразовании в JPEG заполняется белым.
5. При замене фото удалить неиспользуемый asset после успешной транзакции.

Фото остаётся локальным. Для PDF использовать обработанный Blob; для предпросмотра освобождать старые object URL. Отсутствие фото не оставляет пустой рамки в шаблоне.

## 9. Контракт ИИ

### 9.1. Входной DTO

`POST /api/ai/generate`, JSON, `Content-Type: application/json`. Запрос создаётся отдельной allowlist-функцией, а не сериализацией Resume. Вложенные поля проверяются строгими схемами, неизвестные поля отклоняются.

```ts
interface GenerateRequest {
  requestId: string;
  sourceRevision: number;
  consentVersion: string;
  scope: 'all' | 'summary' | 'strengths' | 'experience' | 'skills';
  targetExperienceIds?: string[];
  locale: 'ru';
  source: {
    targetPosition: string;
    summary?: string;
    experience?: {
      id: string;
      company: string;
      position: string;
      start: Month | null;
      end: Month | null;
      current: boolean;
      responsibilities: string[];
      achievements: string[];
    }[];
    skills?: Skill[];
    education?: Education[];
    projects?: { id: string; name: string; kind: Project['kind']; description: string }[];
    courses?: Course[];
  };
}
```

В DTO отсутствуют имя, фото, дата рождения, контакты и URL. По умолчанию скрытые разделы не передаются. Отправляются только источники, нужные выбранной операции; фактические названия организаций и профессиональные даты могут быть нужны для контекста и указаны в согласии.

Свободный текст может содержать введённые самим пользователем персональные сведения. Перед отправкой показывается перечень передаваемых разделов и предупреждение удалить из них лишние данные; обнаруживаемые email и номера телефонов в тексте маскируются локально. Автоматическое удаление всех возможных личных сведений из произвольного текста не гарантируется.

### 9.2. Ответ

```ts
interface GenerateResponse {
  requestId: string;
  sourceRevision: number;
  proposal: {
    summary?: string;
    strengths?: { text: string; evidenceRefs: string[] }[];
    experience?: {
      id: string;
      responsibilities: string[];
      achievements: string[];
      evidenceRefs: string[];
    }[];
    skills?: { sourceSkillIds: string[]; name: string; group: string | null }[];
  };
  questions: { text: string; relatedSourceIds: string[] }[];
  warnings: string[];
}
```

`evidenceRefs` указывают на реально отправленные записи или пункты по стабильному идентификатору, например `experience:<id>:achievement:0`. Сервер строит допустимый набор ссылок и отклоняет неизвестные. В ответе нет операций изменения фактических полей. Новые неподтверждённые навыки допускаются только в `questions`.

Неизвестные ID, несоответствие scope, превышение лимитов, невалидный JSON и новые числовые утверждения приводят к отклонению соответствующего ответа. Проверка чисел сравнивает нормализованные значения в предложении и источниках. Ссылки на источники и программные проверки уменьшают риск выдумок, но не доказывают смысловую достоверность; поэтому пользовательская проверка обязательна.

### 9.3. Серверный адаптер

```ts
interface AiProvider {
  generate(input: GenerateRequest, signal: AbortSignal): Promise<unknown>;
}
```

Системная инструкция требует русский профессиональный текст, 2–4 предложения для описания, сохранение фактов и чисел, отсутствие вымышленных качеств, формат по JSON-схеме и вопросы при нехватке данных. Пользовательский текст передаётся как данные, а не как системная инструкция. У провайдера нет инструментов, доступа к URL или произвольному выполнению кода.

Конфигурация сервера: `AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY`, `AI_TIMEOUT_MS=55000`, `AI_MAX_OUTPUT_TOKENS=3000`, `RATE_LIMIT_REDIS_URL`, `RATE_LIMIT_REDIS_TOKEN`, `RATE_LIMIT_HASH_SECRET`. Секреты не имеют клиентского префикса. Без ключа сервер возвращает `AI_NOT_CONFIGURED`, ручной редактор работает.

### 9.4. Ограничения и ошибки

Начальные лимиты MVP: тело запроса до 128 КиБ, профессиональный текст до 20 000 символов, один активный запрос на сессию, 5 запросов в минуту и 30 в час на анонимную сессию; дополнительный предел — 100 запросов в час на хеш IP. Это технические настройки, не утверждённый коммерческий тариф. При достижении лимита предложить ручное редактирование.

Сессия — случайный HttpOnly cookie с Secure и SameSite=Lax. Счётчики имеют TTL. Для IP используется HMAC с регулярно меняемой солью; сырой IP в хранилище приложения не записывается. При недоступном лимитере AI API возвращает временную недоступность, чтобы не отправлять неограниченные платные запросы.

Ошибки возвращаются как `{ error: { code, message, retryable, fieldErrors? }, requestId }` без текстов резюме и деталей SDK:

- `400 VALIDATION_ERROR` — неверная схема или недостаточно сведений.
- `403 CONSENT_REQUIRED` — отсутствует актуальная версия согласия; `403 ORIGIN_REJECTED` — сторонний Origin.
- `413 PAYLOAD_TOO_LARGE` — превышен размер.
- `429 RATE_LIMITED` — лимит, заголовок `Retry-After`.
- `502 INVALID_AI_RESPONSE` — ответ не прошёл проверку.
- `503 AI_UNAVAILABLE` или `AI_NOT_CONFIGURED` — сервис недоступен.
- `504 AI_TIMEOUT` — превышено время ожидания.

API проверяет Origin относительно разрешённого origin приложения, не разрешает сторонний CORS и не доверяет `requestId` как ключу авторизации. Ответы имеют `Cache-Control: no-store`. Автоматических повторов платного запроса нет; повтор выполняет пользователь. Клиент прекращает ожидание через 60 секунд, серверный deadline — 55 секунд.

### 9.5. Применение и отмена

Предложение хранится отдельно от Resume. После ответа сравнить `sourceRevision` с текущей `revision`; несовпадение показывает «Данные изменились после начала генерации». Для устаревшего предложения доступен просмотр и повторная генерация; применение блокируется.

Применение выполняется одной командой только по разрешённым полям и выбранным разделам, увеличивает revision и сохраняет снимок предыдущих значений. Обязанности и достижения сопоставляются по ID опыта; навыки сохраняют связь с исходными ID. Вопросы ИИ не становятся содержимым документа автоматически.

Одна отмена последнего применения доступна до следующего изменения затронутых полей. После ручной правки этих полей отмена сбрасывается с объяснением, чтобы не потерять новый текст. Правка несвязанных полей отмену не блокирует. Данные undo остаются в памяти и не передаются серверу.

## 10. PDF, шаблоны и предпросмотр

### 10.1. Общий конвейер

`Resume → validateExport → selectVisibleResume → buildDocument → render PDF → preview/download`.

`selectVisibleResume` физически исключает скрытые поля и пустые разделы до создания PDF-дерева. PDF-метаданные содержат только нейтральный заголовок «Резюме», название приложения и техническую версию; скрытые данные не допускаются в метаданные, alt-текст и имена ресурсов.

Предпросмотр и скачивание используют один Blob для одной комбинации revision, формата и версии шаблонов. Скачивание при устаревшем Blob сначала запускает рендер актуальной версии. В worker передаётся снимок видимых данных и фото, внешние ссылки не загружаются.

После паузы ввода 250 мс начинается обновление; устаревшие результаты отбрасываются по ключу задания. При новом задании очередь сворачивается до последнего снимка. Во время рендера предыдущий предпросмотр помечается как обновляемый. Кэш в памяти ограничен двумя последними PDF.

Цель обновления до 500 мс из PRD проверяется на типовом резюме; если полная генерация её не обеспечивает, оптимизировать обновление и повторно измерить. Не заменять точный предпросмотр приближённой HTML-картинкой без отдельного согласования изменения PRD.

### 10.2. Размеры и типографика

- A4: 210 × 297 мм, поля 12 мм, основной текст 11 pt, межстрочный интервал 1,35.
- Mobile: 108 × 192 мм, поля 8 мм, основной текст 12 pt, интервал 1,4.
- Преобразование: `pt = mm × 72 / 25.4`.
- Заголовки разделов — 13–15 pt, имя — 20–24 pt; в Mobile имя может переноситься, а не уменьшаться ниже основного текста.
- Локально поставляемые шрифты с кириллицей, например Noto Sans regular и bold, со встроенной лицензией; сетевые шрифты при экспорте не используются.
- Неподдерживаемые символы выявляются до экспорта: показать конкретные символы и предложить заменить; не заменять их молча пустыми квадратами.

### 10.3. Шаблоны

- Classic: одна колонка, контакты под заголовком, горизонтальные разделители.
- Modern A4: боковой блок шириной около 30% полезной области и основной блок около 66%, промежуток около 4%. В боковом блоке фото, контакты и навыки; остальные разделы в основном.
- Modern Mobile: одна колонка, боковой блок преобразуется в последовательные разделы, акцент сохраняется.
- Minimal: одна колонка, компактные отступы, без крупных фоновых блоков.

В двухколоночном шаблоне порядок PDF-текста задаётся семантической последовательностью, а не случайным порядком рисования. Подтверждается извлечением текста. Если движок не позволяет обеспечить это вместе с переносами, технический прототип считается неуспешным и движок меняется; требование не снимается.

### 10.4. Палитры

Общий фон `#FFFFFF`, основной текст `#202124`, вторичный `#4B5563`. Акцент: graphite `#374151`, blue `#1D4ED8`, green `#166534`, burgundy `#9F1239`, purple `#6B21A8`. Светлые заливки определяются отдельно; на них используется тёмный текст. Все фактические сочетания текста и фона проверяются на контраст не ниже 4,5:1.

### 10.5. Пагинация

Заголовок раздела удерживается минимум с первыми двумя строками содержимого. Короткая запись переносится целиком при нехватке места; запись выше полезной высоты страницы делится по абзацам и пунктам. Нельзя применять запрет разрыва ко всей потенциально длинной записи. Длинные слова и URL переносятся по допустимым границам с резервным разбиением по символам.

Не уменьшать шрифт автоматически ради одной страницы. Нумерация «Страница N из M» выводится только при M > 1 и занимает зарезервированную область нижнего поля. Большие резюме получают дополнительные страницы без жёсткого ограничения количества в пределах лимитов модели.

### 10.6. Скачивание

Возвращается `application/pdf`. Имя строится из полного введённого имени без попытки определить фамилию: `Резюме_<полное_имя>_A4.pdf` или `_Mobile.pdf`. Пробелы заменяются подчёркиваниями, управляющие и запрещённые файловые символы удаляются, основа ограничивается 100 символами. При пустом безопасном имени используется `Резюме`.

Ссылки создаются PDF-аннотациями: `mailto:`, `tel:`, `https:` или `http:`. При размере выше 5 МБ показать предупреждение и предложить уменьшить фото; скачивание не блокировать, так как 5 МБ — целевой размер типового документа. После завершения скачивания object URL освобождается с задержкой, достаточной для мобильного браузера.

## 11. Безопасность и эксплуатация

- HTTPS на production, секреты задаются окружением размещения.
- CSP разрешает только необходимые собственные ресурсы, PDF Worker и blob-ресурсы; не использовать произвольные сторонние скрипты.
- Пользовательский текст выводится как текстовые узлы. Не использовать `dangerouslySetInnerHTML` для полей и ответа модели.
- Сборщики ошибок исключают тела запросов, состояние формы, заголовки cookie и секреты. Запись пользовательских сессий отключена.
- Логи сервера: requestId, код результата, длительность, обезличенные счётчики токенов; без prompt и ответа.
- В аналитике допустимы только названия событий, формат, templateId, themeId, статус и длительность. Данные полей, URL портфолио и filename не отправляются.
- События: `editor_started`, `ai_requested`, `ai_completed`, `ai_failed`, `ai_applied`, `pdf_requested`, `pdf_completed`, `pdf_failed`, `template_changed`, `theme_changed`.
- ИИ-провайдер и его условия хранения указываются в политике до включения публичной генерации. До этого AI-функция выключена конфигурацией.

Размещение должно поддерживать серверный запрос до 55 секунд и необходимые лимиты тела API. Постоянная база резюме и серверный PDF-эндпоинт не создаются. Не добавлять service worker, кэширующий API или персональные данные, в MVP.

## 12. Проверки и трассировка к PRD

### 12.1. Модульные и интеграционные проверки

- Модель: даты, видимые и скрытые записи, дедупликация навыков, сортировка и контекстная валидация — PRD 7, 15.3.
- Хранилище: восстановление, атомарная замена фото, ошибка quota, конфликт вкладок, удаление во время активных операций — PRD 12, 15.1, 15.13.
- AI DTO: отсутствие персональных полей и скрытых разделов, маскирование распознаваемых контактов, строгая серверная схема — PRD 13, 15.12.
- AI response: неизвестные ID, новые числа, лишние поля, неверный scope, невалидный JSON, тайм-аут и 429 — PRD 8, 15.4–15.6.
- Применение: отдельные разделы, stale-предложение, ручные правки, отмена — PRD 8.3–8.4.
- PDF: размеры страниц, наличие встроенных шрифтов, извлекаемый текст, порядок чтения, аннотации ссылок и отсутствие скрытого содержимого — PRD 11, 15.8–15.11.

### 12.2. Наборы данных

Использовать синтетические данные без реальных персональных сведений:

1. Минимальное резюме без фото и даты рождения.
2. Выпускник без опыта с учебными проектами.
3. Типовое резюме из PRD: 5 мест работы, 3 образования, 30 навыков, до 10 000 знаков и фото.
4. Длинное резюме на несколько страниц с длинными именем, URL и отдельной записью выше одной страницы.
5. Смешанная кириллица и латиница, диакритика и неподдерживаемый символ.
6. Все скрытые разделы заполнены контрольными маркерами, которые должны отсутствовать в PDF.
7. Вредоносный HTML, опасные URL и инструкции модели внутри текста.

### 12.3. Визуальная и браузерная приёмка

Автоматически сгенерировать все 30 сочетаний: 3 шаблона × 5 тем × 2 формата. Проверить без фото, с фото и с длинным текстом. Отрендерить PDF в изображения для визуальной оценки разрывов, наложений и обрезки; проверки по изображениям дополняют, а не заменяют извлечение текста.

Пользовательские сценарии проходят при ширинах 360, 390, 768 и 1440 px. Проверить актуальную и предыдущую версии Chrome, Edge, Firefox и Safari, отдельно Chrome Android и Safari iOS. PDF открыть в настольном и мобильном просмотрщике; проверить скачивание, масштаб по ширине и ссылки.

### 12.4. Производительность

Зафиксировать модель тестового устройства, ОС, браузер и сеть в отчёте. Измерять от конца ввода до актуального предпросмотра, от запроса до предложения и от нажатия скачивания до готового файла. Для p95 использовать минимум 30 повторов типового сценария с указанием объёма выборки. Цели: предпросмотр до 500 мс, AI p95 до 30 секунд, PDF p95 до 10 секунд; тайм-аут AI 60 секунд.

Генерацию проверить на фиксированном наборе фактов: модель не добавляет работодателей, квалификации, стаж и числовые результаты, не подменяет проект трудоустройством и задаёт вопросы при недостатке данных. Моки применяются для воспроизводимости интерфейсных тестов; перед запуском дополнительно проверяется реальный выбранный провайдер.

## 13. Порядок реализации и готовность

1. **Технический прототип PDF:** оба размера, шрифты, Modern на нескольких страницах, извлечение текста, Worker на мобильном Safari. Результат — подтверждённый движок и короткий отчёт с образцами.
2. **Домен и черновик:** схемы, команды, IndexedDB, миграции, фото, конфликты вкладок. Результат — восстановление данных и корректное удаление.
3. **Редактор:** все разделы, адаптивная компоновка, проверки, доступность и ручное создание резюме.
4. **Оформление:** три шаблона, пять тем, точный предпросмотр и оба скачивания. Результат — готовый сценарий без ИИ.
5. **ИИ:** адаптер, ограничения, согласие, строгие DTO, предложения, применение и отмена. Результат — генерация не перезаписывает данные без действия пользователя.
6. **Приёмка:** сценарии раздела 12, отчёт о производительности, политика данных и проверка production-конфигурации.

MVP готов, когда выполнены 14 критериев раздела 15 PRD, пройдены проверки безопасности и PDF, настроен выбранный провайдер и зафиксированы результаты тестирования. Наличие этой спецификации не означает прохождение проверок.

## 14. Оставшиеся параметры запуска

- Выбрать ИИ-провайдера, модель, бюджет и утвердить условия обработки данных.
- Выбрать хостинг с необходимым временем серверных запросов и Redis-совместимое хранилище счётчиков.
- Подтвердить PDF-движок по результатам прототипа; первоначальный выбор указан в разделе 2.
- Утвердить бренд и при необходимости скорректировать визуальные токены без изменения контрактов.

Остальные решения в документе служат рабочими значениями для реализации MVP. Публикация, платные подключения и развёртывание не выполняются в рамках подготовки спецификации.
